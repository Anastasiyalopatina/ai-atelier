# ai-atelier: правила разработки

Имя приложения и целевого нового репозитория — `ai-atelier`.
Текущая стадия — Bootstrap; фактическое состояние в docs/BOOTSTRAP_STATUS.md.

1. Единственный модельный исполнитель — официальный локальный Codex с
   управляемой авторизацией ChatGPT. Не использовать API-ключи, извлечение
   токенов/cookies, недокументированные endpoints или платные обходные пути.
2. Пока безопасность автоматического платного продолжения не подтверждена,
   не выполнять модельные задания. `scripts/doctor.mjs` намеренно разрешает
   только чтение статуса, каталога и лимитов.
3. Данные пользователей, память, базы, исследования, содержательные логи,
   экспорты, резервные копии и авторизация должны находиться вне Git. Для
   тестов использовать отдельные временные директории и вымышленные данные.
4. Не публиковать ничего до явного allowlist файлов, проверки секретов,
   staged diff и всей истории первого push. Цель публикации после проверки
   прав и отсутствия конфликта имени — новый публичный репозиторий
   `Anastasiyalopatina/ai-atelier`.
5. Не объявлять BOOTSTRAP_READY без реального модельного цикла,
   восстановления результата после перезапуска, работающего каркаса,
   проверенных команд и подтверждённой публикации. Моки этого не заменяют.
6. На реальном блокере подготовить диагностику и остановить Bootstrap.
   Не создавать рабочие чаты/ветки до проверенного общего bootstrap commit.

## Будущее распределение владельцев

- Lead: `apps/server`, `packages/memory`, `packages/codex-bridge`,
  `packages/mcp`, `packages/contracts`, корневые manifest/lockfile,
  общие конфиги и миграции БД.
- UI: `apps/web`, `docs/ux`.
- Research: `packages/research`, `docs/research`.
- QA: `tests/e2e`, `tests/security`, `tests/evals`, `docs/qa`.
- `docs/handoffs/<role>.md`: соответствующий участник.

Другие роли работают в отдельных именованных ветках и worktree от одного
проверенного bootstrap commit. Не менять общие contracts и lockfile без Lead,
не коммитить в main и не мержить соседние роли. Этот диагностический этап ещё
не является исходной точкой для передачи работы.
