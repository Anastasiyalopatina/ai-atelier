# Архитектура Bootstrap

React/Vite и небольшой Node.js backend с одним origin. Приложение и contracts —
TypeScript; диагностика — ESM. Node.js 24+ исполняет erasable TypeScript.
SQLite встроенный (`node:sqlite`); внешней БД, embeddings и телеметрии нет.
Зависимости зафиксированы в корневых package.json / package-lock.json.

## Модули

- packages/contracts: contracts **1.0.0**, схема **1**. Типы памяти, evidence,
  источников/локаторов, proposals, context, research и runtime. Меняет только Lead.
- packages/memory: миграция v1, операции проектов/задач. Составные foreign keys
  запрещают связи evidence между проектами. Для знаний/источников/proposals
  создана схема; CRUD и алгоритмы версий ещё не реализованы.
- packages/codex-bridge: один официальный App Server через stdio. Проверки
  account/read, model/list, account/rateLimits/read; затем thread/start и
  turn/start с JSON Schema. Принимается только completed, JSON проверяется кодом.
- apps/server: loopback, сессионный ключ, Host/Origin, ограничение JSON body,
  CSP и allowlist статических assets. React выводит текст; raw HTML не вставляется.

## Исполнение

Только managed ChatGPT. API-key и external-token режимы не принимаются.
forced_login_method=chatgpt применяется к thread config после проверки аккаунта.
Маршрут выбирает официальный клиент; нестандартные адреса блокируются.
Глобальный конфиг не меняется. Системный прокси и CA сохраняются; API-ключи и
провайдерные переменные исключены. auth.json не читается приложением.

ModelQueue: один активный исполнитель, до 20 ожидающих задач, 12 000 символов
контекста, 150 секунд на turn, без автоматических повторов/исправлений.
Межпроцессный lock общий для приложения и probes. Второй сервер с той же
директорией блокируется. Статусы, версия/хеш входа и результат сохранены.
После сбоя queued/running становятся interrupted; повтор требует действия.
Идемпотентный ключ возвращает прежнюю задачу. Shell, MCP, apps, hooks,
browser/computer use, изображения, память клиента и делегирование выключены.
Рабочая папка содержит только подготовленные вымышленные данные.

Перед запуском требуется ручное подтверждение отключённого платного продолжения
и автопополнения, действующее 24 часа. API не подтверждает эти настройки.
Кредиты и лимиты не заменяют проверку. Покупки, resets и письма о пополнении
не вызываются. Ошибки авторизации, лимита, сети, JSON и stale input различаются.
Платного fallback нет; отсутствующая телеметрия считается неизвестной.

## Данные и ограничения

Все runtime-файлы вне Git, включая БД, подтверждение биллинга и локальный сеанс.
Пути внутри Git, в том числе через symlink, отвергаются. SQLite/авторизация
официального клиента остаются у него. Ключ сеанса передаётся launcher через
fragment, затем хранится в sessionStorage вкладки. Он не публикуется и не
выводится в логи. Источники/логи с содержимым не публикуются.

Временные папки удаляются в finally. После аварии, остановив приложение, можно
удалить оставшиеся task-workspace- / synthetic-workspace- / web-probe- папки
в выбранной директории данных. Для удаления всех данных остановите приложение,
сделайте нужную копию и удалите только директорию данных ai-atelier. Не трогайте
авторизацию Codex или соседние проекты. Интерфейс backup/restore ещё не готов.

Защита не рассчитана на вредоносный процесс того же пользователя с правом читать
его файлы. Абсолютные гарантии безопасности и биллинга невозможны. Каталог
может быть кеширован; доступ доказан только реальным завершённым turn.
Live search в проведённом probe не подтверждён.

Fetch URL и импорт пока отсутствуют. Их нельзя добавлять без защиты SSRF,
проверок DNS/private IP/redirect, traversal, размера и типов файлов. local-only
материалы не должны попадать в модель, поисковые запросы или логи.
Реальная регистрация MCP отложена до интеграции backend.
