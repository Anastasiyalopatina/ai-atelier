# Research 1.0.0

Пакет реализует два процесса: `analyze_report` извлекает находки из указанных
фрагментов отчёта; `new_research` сравнивает 2–3 инициативы по предоставленным
источникам. Оба возвращают `ResearchArtifact` с contracts v1 `ResearchResult`,
полными карточками, историей, проверками, действиями и предложениями памяти.
Никакие данные не сохраняются и не принимаются автоматически.

Этапы: planner → ограниченный collector → analyst → reviewer в отдельном
контексте → editor → повторная проверка. Вызовы последовательны через один
переданный адаптер. Нет сети, запуска Codex, API-клиента, зависимостей, покупки
поиска, дочерних исполнителей или повторов. Предоставленные материалы —
недоверенные данные; шаблоны ролей версии 1.0.0 отделены от payload.

## Вход и одобрение

`ResearchInput` содержит неизменённый `ResearchRequest`/`ContextSnapshot`,
`sources`, `fragments` с дополнительным `sourceVersion`, `sourceStates`,
`reportFragmentIds`, `settings` и `approvedInputSha256`. См. `src/types.ts`.
Снимок, решения, критерии и ограничения не изменяются. Planner может предложить
новые критерии только отдельно в `proposedCriteria`.

Backend готовит предпросмотр **всего** входа и получает согласие пользователя.
`inputDigest(input)` канонически хеширует снимок, тексты, настройки и выбор
отчёта. Одобрение только старого ContextSnapshot не разрешает передачу новых
источников. Изменение любого поля после одобрения вызывает `STALE_INPUT`.
Пакет отвергает `local_only` до первого вызова; не скрывает и не отправляет их
автоматически. Backend должен отбирать разрешённые материалы заранее.

JSON Schema замкнуты, без coercion и лишних полей. Типы и проверки задаются
одним локальным описанием. `validateInput` доступен отдельно. Тексты ошибок
содержат коды/путь поля, не исходные материалы или стек внешнего исполнителя.

## Очередь и интеграция

Текущий `ModelQueue` Bootstrap исполняет только задачу «Лунный сад», поэтому
**пакет ещё не подключён к backend и реальная модельная оценка не выполнена**.
Один старый `RuntimePort.run({context, role})` не передаёт stage payload и
JSON Schema. Для согласования без изменения чужих contracts введён локальный
`ResearchRuntimePort` с маркером `protocol: 'ai-atelier.research.stage.v1'`.
Его request расширяет аргумент общего `RuntimePort`; снимок и его hash исходные.

Lead должен реализовать очередь, которая понимает `research` envelope:

1. Проверяет общее одобрение, версию проекта, managed ChatGPT, лимиты и ручное
   подтверждение отключённых платных продолжений. Не использует платный fallback.
2. Учитывает в общей очереди **каждый** stage; объединяет trusted `template` с
   явной JSON-секцией недоверенного `payload` и исходным `context`.
3. Передаёт `outputSchema`, использует новый контекст/thread для каждого stage,
   обязательно отдельный для reviewer; не продолжает предыдущую беседу.
4. Выполняет cancellation/timeout, завершает активный turn, хранит input hash,
   role/template version/hash, статусы и результаты вне Git. Не повторяет stage
   автоматически. Ошибки auth/usage/network сохраняет раздельно.

Пакет требует явного маркера адаптера и не позволяет случайно подключить
bootstrap runtime, проигнорировавший envelope. Он не может доказать, что
переданный адаптер соблюдает этот договор; это отдельная интеграционная проверка.

Бюджет по умолчанию: 7 вызовов, максимум 3 collector, 64 находки, 12 000 символов
полного stage envelope, 150 секунд на stage. Четыре вызова зарезервированы
для planner/analyst/reviewer/editor. `analyze_report` требует хотя бы одного
collector. При достаточности по **модельной оценке** сбор прекращается;
интервью, внутреннее уточнение, расчёт и пилот остаются отдельными действиями.
Исчерпание бюджета и оставшиеся пробелы видны в артефакте. Ограничение не
обходит общую очередь: интегратор проверяет её более строгий лимит. Большой
снимок требует явной адресной выборки и нового согласия, иначе
`CONTEXT_BUDGET_EXCEEDED`. Тестовый предел 120 000 не означает, что очередь его
поддерживает. Встроенного автоматического чанкинга нет.

## Доказательства, расчёты и память

`stableSourceId(origin)` и `stableFragmentId(sourceId, version, location, text)`
дают повторяемые IDs. Поддерживаются версии одного source ID, локаторы текста,
PDF, DOCX и таблицы. Хеш каждого текста проверяется; полное содержимое источника
пакету неизвестно, поэтому его общий sha256 считается метаданными интегратора.
SourceState различает предоставление, находку, получение и недоступность;
finding отдельно отражает заявленную моделью поддержку/противоречие.

Проверяются project/source/version/chunk связи, доступность полного текста,
буквальная цитата, дубликаты и линии происхождения, устаревание/замена версий,
обязательные блоки, известные ссылки, числа без основания и единицы.
Сниппет и URL сами по себе не являются доказательством. Публикация, получение
и событие хранятся отдельно. Новая версия не стирает предыдущую.

Буквальное совпадение цитаты **не проверяет логическую поддержку**. Все
`evidenceChecks.semanticSupport` остаются `model_only_unverified`, а итог
никогда не получает `verified`. Проверка смысла, полноты рынка, допустимости
использования данных и причинных переходов требует reviewer и человека.
Эвристики чисел/отсутствия аналогов не являются полным NLP-анализом.

Формулы — ограниченная postfix-программа: named inputs и четыре арифметические
операции, до 100 tokens. `eval`, функции, произвольные строки не исполняются.
Проверяются стек, деление на ноль, конечность, результат и размерности.
Единицы: `RUB`, `item`, `hour`, `RUB*month^-1`, `1`. Month/year и валюты не
конвертируются автоматически. Текст формулы восстанавливается из программы.
Допущения и исходные единицы остаются в расширенном артефакте; общий contracts
v1 economics не вмещает их полностью.

Редактор выбирает существующие абзацы/основания и порядок всех claims, не
создаёт новый текст. Полные риски, неизвестное, исходный анализ и коллекции
сохраняются; исключённые абзацы отмечаются. Успешное резюме — не более заданного
предела (по умолчанию 500 слов, подсчёт по пробельным токенам). Неудачное
сокращение вызывает `SUMMARY_LIMIT_EXCEEDED`, без повторного модельного вызова.

`add_finding` даёт pending/conflict, `review_existing` всегда conflict и
сохраняет исходную запись. Пути `/research/findings/<id>` и
`/research/review/<id>` — **локальное предложение для согласования**, не
готовый backend patch API. Нельзя применять их напрямую к канонической памяти.
`rebaseProposals` отмечает stale baseVersion; project/version CAS и финальное
принятие по явному действию пользователя реализует backend.

## Проверки и ограничения

`npm run test:research` — синтетические детерминированные тесты без модели.
`npm run typecheck`, `npm run build`, `npm test` — совместимость с bootstrap.
Публикационная проверка роли:
`node packages/research/scripts/check-publication.mjs`.
Корневой PUBLIC_FILES.txt не изменён: дополнение роли находится в
`docs/research/PUBLIC_FILES.txt`; Lead должен включить его при интеграции.

Нет реального поиска или загрузки URL, импорта, CRUD памяти, DB migrations,
UI/backend routes и пользовательской приёмки. Внешние находки должны сначала
пройти безопасное получение/версирование у интегратора. Защита от prompt
injection — транспортная граница и инструкции, не доказанная устойчивость
модели. Содержательные логи, результаты прогонов и исходные пользовательские
материалы остаются вне Git.
